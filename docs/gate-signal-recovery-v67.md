# v67 门禁与缺失数据修复（S1/S3）

对应 architecture-simplification-execution-plan-v1.md 的 S1 唯一事实/决策出口与 S3 Pin 语义。用户明确要求修复门禁、缺失数据和表达，使合格输入能够形成信号；不以任意放宽价格或事件门替代修复。

## 修改合同

- Pin LOOK 是未确认观察，不能单独否决独立已授权方向价差。PIN_STABLE 保留方向保护。未授权 setup 仍拒绝，蝶式确认门不变。
- 铁鹰首次锁腿须同时满足既有结构、价格、风险及平衡/扩张转收缩环境。旧版本未获选的提前锁不继承；已选铁鹰保留。日内次数、入场窗口不变。
- ready + 没有 setup = WAITING_FOR_TRIGGER；实际缺数据保留 INSUFFICIENT_DATA；候选未过门为 CANDIDATE_REJECTED，不再把事件/权限拒绝一律写成赔率差。混合环境不再声称所有方向结构关闭，缺失字段明确显示。
- 近 ATM 最多既有 hot_option_limit 个期权报价配成同源 Call/Put，对每个执行价保存跨式 mid 和 provider，复用现有滚动 JSON 历史。15 分钟对照使用当前 ATM 执行价在历史中的同一合约，避免换 ATM 时将两个不同结构相减。历史 frame 距离目标超过 90 秒拒绝，避免把中断之前的观察冒充 15 分钟变化。
- 该指标仍是含标的位移/时间价值变化的跨式变化，不是纯 IV 衰减或 dealer 净 Gamma。仅作已有输入，不创造方向。

## 兼容和运行边界

滚动历史旧记录没有逐执行价报价表，首次部署需要积累新的可比历史；不猜测或从事后期权表倒灌。新表保留在现有行情状态，没有新数据库、服务、依赖或并行 owner。Bark 不读取、不修改、不测试发送。现有策略门禁测试仅验证人工候选输出，不证明正期望。

## 验收
