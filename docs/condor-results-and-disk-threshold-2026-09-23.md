## 为什么桌图只有7–9日

原桌图路径模型把当前四腿报价锚定到过去同钟的标的/IV曲面路径，模拟当前管理规则。
它不是上表逐日实际选择并用原始四腿BBO退出的历史回测。

00:45 UTC 的当前结构快照：贷记2.10点，9/9条路径盈利并止盈、0/9止损，
模拟净收益中位数$110.78。这应直接展示为历史模拟频率，而不是被样本阈值全部隐藏。

00:48:39 UTC 固定时点审计：

1. 库中能索引到51个历史曲面session，绝不是只采集了7天。
2. 原35天窗口加跨夜缓冲，只扫描到其中26个session。
3. 当时从20:48 ET到次日12:30需要190个五分钟目标点；任一点缺失就排除整天。
4. 短窗口最终仅7日；用全部已有历史则12日。
5. 全历史被排除的39日中，30日其实覆盖超过90%的目标点；部分日期只缺1–2点。

这是短窗口及全路径完整性筛选造成的缩水。不同分钟的目标网格不同，也解释了7/9的变化。
本次取消铁鹰展示估计的35天裁剪，后台使用已有全部历史；原始时间边界、缺口判断保留。
缺口后的未知收益不补成0，不拼接当天/未来数据。处理“已退出后的缺口不应排除该日”
仍需支持逐路径不同终点的回放，目前矩阵加载器尚未完成这项改进。

桌图对 `insufficient_sample` 和 `estimated_uncalibrated` 都显示有效的盈利/止盈/止损频率，
小样本只附“X日、小样本、未校准”，不再以样本量隐藏结果。
未知/非法数据或退出合同不匹配仍不能生成百分比。无报价时按实际原因说明，
不把缺标的、到期日或策略结构一律误报成“四腿报价未就绪”。
本次核验生产当前四腿报价READY；“缺少合格报价”不是本次快照无百分比的原因。

## 空间行为

Python warning/critical 和 Rust 写入后保留空间统一为10 GiB。Python在剩余恰好10 GiB时
不进入warning/critical；低于才进入。Rust会拒绝导致写后低于10 GiB的追加。
维护告警也以绝对可用字节检查，不再仅因磁盘使用百分比高就告警。
28 GiB的既有已验证归档清理触发线保留，它只提前清理授权冗余，不限制策略通知。
没有修改 Bark transport、通知目的地或候选权限。
